## 1. 背景与目标

苏州古城（护城河以内，面积约 14.2 km²，南北约 4600 m、东西约 3400 m）拥有高度可辨识的空间格局："三纵三横一环"水系、略带屈曲的长方形城形、54 个街坊肌理，以及拙政园、留园、盘门等一批高辨识度景点。这些要素目前缺少一个"打开即见全貌、拉近可看细节"的轻量化浏览载体。

本产品是一个**基于网页的 3D 数字沙盘**：以 OSM 真实地理数据为底，经 Blender 艺术化处理后，在浏览器中以可交互三维沙盘呈现姑苏古城的整体格局与重点景点。

**可观察的目标结果**（不虚构量化指标）：

- 用户打开页面即可看到正确的古城轮廓与"三纵三横一环"水系；
- 用户可以在俯瞰全景与拉近查看景点之间平滑缩放，过程中不出现明显卡顿；
- 用户可以点击任意 P0 景点，看到聚焦动画与景点信息；
- 在主流笔记本集显上稳定可用（见第 5 节性能需求）。

## 2. 产品定位与核心体验

| 要素 | 定义 |
| :--- | :--- |
| 主要用户 | 对苏州古城格局与景点感兴趣的浏览者（文化爱好者、游客、展示汇报观众）`[假设, TBD]` |
| 触发 | 在浏览器中打开沙盘页面 |
| 核心任务 | 以俯瞰视角浏览古城整体格局，定位并了解重点景点 |
| 完成标志 | 能看到完整城形与水系；能找到全部 P0 景点并读取其信息 |
| 共享对象 | 沙盘场景（底座 + 水系 + 风格化建筑群 + 景点模型 + 标签） |
| 使用设备 | 桌面浏览器为主；移动端降级为 P2 |

本产品**不追求**逐栋民居的真实还原与逐栋可点击——沙盘的"全貌"体验不依赖于点击每一栋民居（详见第 3 节排除项）。

## 3. 范围

### 3.1 P0 —— 最小完整体验

| 编号 | 内容 |
| :--- | :--- |
| S-01 | 古城轮廓底座 + 环城水系 + 坐标系锁定 |
| S-02 | 全域风格化建筑群（屋顶群 + 密度肌理） |
| S-03 | 4 个 P0 景点精细模型：拙政园、留园、盘门（瑞光塔 + 水陆城门）、平江历史街区（样板段） |
| S-04 | 轨道控制（俯瞰/缩放/旋转） |
| S-05 | 景点射线拾取 + 高亮 + 信息面板 |
| S-06 | 景点标签（CSS2D），L0/L1 显隐层级 |
| S-07 | 景点聚焦动画（点击→拉近，可返回全景） |
| S-08 | 三级 LOD + 分块异步加载，首屏快速呈现全貌 |

### 3.2 P1 —— 增强

- 4 个 P1 景点：网师园、狮子林、山塘街（阊门—虎丘段）、苏州博物馆；
- 标签遮挡处理（被前方建筑挡住时降低透明度）；
- L2 景点子标注（如"远香堂""冠云峰"）；
- 建筑群实例点击（`instanceId` → OSM id → HUD），若性能预算吃紧可降级（见 6.4）。

### 3.3 P2 —— 后续

- 沧浪亭、寒山寺（寒山寺是否纳入取决于主城范围是否扩展到阊门外枫桥，见第 7 节）；
- 移动端降级方案；
- 纹理/光照进一步打磨。

### 3.4 明确排除

- 全域每栋民居的精确轮廓与真实高度（以风格化屋顶群替代）；
- 每栋民居的可点击信息查询；
- 实时/动态数据接入、用户账号与内容编辑；
- 复杂的 UI 状态管理（景点信息为静态内容，侧边栏/HUD 展示即可）。

## 4. 功能需求

### 4.1 场景基底

**FR-01 沙盘底座**

- 以古城轮廓多边形（从护城河 OSM 数据提取）生成"抬升的沙盘底座"，底面加一圈厚度，呈现实体沙盘台观感；
- 底座外侧放置简化的环城河水面；
- 坐标基准：古城边界取 **120.5979°E–120.6447°E，31.2868°N–31.3345°N**（中研院 GIS 苏州城图 bounds，与护城河以内范围吻合）；
- 场景原点取古城几何中心（约 **120.621°E, 31.311°N**），局部墨卡托或简单等比缩放，**1 单位 = 1 米**，LOD 距离参数按真实尺度设定。

**FR-02 水系**

- 完整保留"三纵三横一环"水系（OSM waterway 数据）；
- 水系使用略深材质 + 轻微反光，作为全场视觉锚点；
- 水系是首屏必须呈现的元素，不参与按需加载。

### 4.2 建筑层次

**FR-03 全域风格化屋顶群**

- 全域建筑不逐栋精确拉伸，呈现为**统一坡屋顶语言的风格化屋顶群**；
- 屋顶群的分布须反映真实 OSM 建筑密度：密集民居、园林绿地、主干道三类区域可被肉眼区分（由 OSM building footprints 密度栅格化驱动）；
- 街巷与水系网络作为底图肌理保留。

**FR-04 重点片区**

- 划定精细区：**平江路、山塘街、拙政园—狮子林片区**；
- 精细区内使用真实 OSM 建筑轮廓做较高精度体块，精度高于全域屋顶群；
- 精细区与景点模型的关系遵循 FR-05 的"嵌入"规则。

### 4.3 景点模型

**FR-05 景点清单与呈现**

景点数量控制在 **8–12 个**，清单与优先级如下（本表为景点优先级的唯一权威定义）：

| 景点 | 类型 | 优先级 | 说明 |
| :--- | :--- | :--- | :--- |
| 拙政园 | 园林 | P0 | 沙盘东部视觉重心，水系和亭廊轮廓需手工处理 |
| 留园 | 园林 | P0 | 西部锚点，冠云峰和曲廊的体量关系是识别关键 |
| 平江历史街区 | 街区 | P0 | 不需每栋建模，沿河立面需一段"样板段"精细处理 |
| 盘门（瑞光塔 + 水陆城门） | 地标 | P0 | 古城西南角唯一"垂直地标"，塔是沙盘天际线关键 |
| 网师园 | 园林 | P1 | 中小型园林代表，展示"精致度" |
| 狮子林 | 园林 | P1 | 假山群几何复杂度高，需控制面数 |
| 山塘街（阊门—虎丘段） | 街区 | P1 | 西北方向线性地标，可做带状简化模型 |
| 苏州博物馆 | 现代地标 | P1 | 与拙政园相邻，体量简洁，低模即可传达特征 |
| 沧浪亭 | 园林 | P2 | 南部锚点，复廊和水面关系有辨识度 |
| 寒山寺 | 宗教 | P2 | 位于阊门外，是否纳入取决于主城范围是否扩展到枫桥 |

规则：

- 景点定位以 OSM `tourism=attraction` / `historic=*` 节点坐标为基准，世界遗产（拙政园、留园、网师园）可用公开经纬度记录校验；
- 景点模型与 OSM 底模的关系是**"嵌入"而非"覆盖"**：底模对应位置的建筑体块置空或压平，再放置精细模型，不允许出现 z-fighting；
- 每个景点模型面数预算 **5k–30k 三角面**（不含植被），在 L2 视距下轮廓可读。

### 4.4 相机与导航

**FR-06 轨道控制**

- 开启阻尼（惯性）；
- 限制俯仰角，镜头不得穿到地面以下；
- 最近/最远距离与 LOD 的 L2/L0 切换阈值对应：拉远到全景、拉近到景点细节均在允许范围内；
- 默认视角为俯瞰古城全貌。

### 4.5 拾取与高亮

**FR-07 点击拾取**

- 点击景点模型或景点标签 → 该景点高亮并触发聚焦（见 FR-09）；
- 高亮方式：修改材质自发光（emissive）；共享材质必须先克隆再修改，禁止"串亮"（点击 A 景点导致 B 同时发亮）；
- 再次点击空白处或执行"返回全景"后高亮解除；
- （P1）点击建筑群实例：通过 `instanceId` 解析对应 OSM id 或自定义数据，触发 HUD 面板；该项在性能预算吃紧时可整体降级关闭（见 6.4）。

### 4.6 标签系统

**FR-08 景点标签**

- 使用屏幕空间 HTML 标签（CSS2D 方案）钉在 3D 坐标上：文字锐利、样式由 CSS 控制、不烘焙进纹理；
- 显隐层级规则（唯一权威定义）：

| 视距层级 | 显示内容 |
| :--- | :--- |
| L0（>800 m） | 仅 P0 景点标签 |
| L1（200–800 m） | 全部景点标签 |
| L2（<200 m） | 景点标签 + 景点内子标注（如"远香堂""冠云峰"） |

- （P1）遮挡处理：标签位置被前方建筑挡住时降低透明度，避免俯瞰时标签"浮"在无关区域上。

### 4.7 景点聚焦与信息

**FR-09 聚焦动画与信息面板**

- 点击景点标签或模型后，相机平滑聚焦到该景点包围盒；
- "返回全景"用同一套动画反向执行；
- 聚焦期间侧边栏/HUD 展示该景点的**静态信息**：名称、简介、是否世界遗产；
- 信息内容在构建期准备好，不依赖运行时接口。

### 4.8 加载与 LOD 体验

**FR-10 加载策略**

- 首屏只加载：底座 + 水系 + 全域 L0 占位，用户打开页面即可看到古城全貌；
- 加载进度可见（进度指示）；
- 景点模型与精细建筑块**异步按需加载**，不阻塞首屏。

**FR-11 三级 LOD**

| 层级 | 视距 | 呈现内容 |
| :--- | :--- | :--- |
| L0 | >800 m | 底座 + 水系 + 建筑群极简实例（每栋一个 box 或单坡屋顶）+ 景点占位体块；总 draw call ≤ 20 |
| L1 | 200–800 m | 建筑群切换为带屋顶语言的实例（坡顶、平顶两类）；景点显示中模（约 2k–5k 面） |
| L2 | <200 m | 景点切换高模；视锥内仅保留近处 200–300 栋建筑实例，远处实例留在 L1 层级 |

- 层级切换过程中不得出现明显卡顿或画面跳变。

## 5. 性能需求（硬性预算）

性能是本产品的核心约束，所有美术与功能决策在冲突时让位于以下预算：

| 指标 | 预算 |
| :--- | :--- |
| 帧率 | 主流笔记本集显稳定 ≥ 30 FPS，独显 ≥ 60 FPS |
| Draw call | L0 全景 ≤ 20（M1 阶段验收 < 30） |
| 纹理总内存 | ≤ 100 MB（WebGL 上下文安全区） |
| 景点模型面数 | 每个 5k–30k 三角面（不含植被） |
| 景点中模（L1） | 约 2k–5k 面 |
| 几何压缩 | 建筑群 GLB 使用 Draco 压缩（压至原体积 20–30%） |
| 纹理压缩 | 景点关键纹理使用 KTX2（Basis Universal）；HDRI 使用 2K |
| 建筑底模材质 | 优先顶点颜色或纯色材质，不用贴图 |

## 6. 共享规则与异常

### 6.1 数据规则

- OSM 建筑**无高度标签**不是错误：该类建筑统一归入风格化屋顶群处理（Blender 导入工具的 fallback 高度仅用于过渡）；
- OSM 高度异常值（如误标 `height=200`）在建模清洗阶段压回合理范围，不进入运行时；
- 重复顶点在建模阶段焊接（Merge by Distance），运行时不做几何修复。

### 6.2 高亮规则

- 任何高亮都不得污染共享材质：先克隆、再修改（FR-07 的执行细则，全场景唯一规则）。

### 6.3 加载异常

- 单个分块加载失败：不阻塞首屏与已加载内容，允许重试 `[假设, TBD：重试 UI 形态待定]`；
- 景点模型加载未完成时，该位置显示 L0 占位体块，不得出现空洞或闪烁。

### 6.4 降级规则

- 若建筑群实例化后 draw call 仍超出预算：降级为"按材质合并的整体 mesh"，放弃逐栋拾取，仅保留景点与关键街区的可拾取性（降级决策点在 M1 验收，见开发流程）。

## 7. 开放问题

| # | 问题 | 影响 |
| :--- | :--- | :--- |
| Q1 | 主城范围是否扩展到阊门外枫桥一带 | 决定寒山寺（P2）是否纳入 |
| Q2 | 是否采购 Blender-OSM（blosm）premium 版 | 影响建模效率与材质成本，不影响产品行为 |
| Q3 | 网页端采用 @react-three/fiber 还是原生 Three.js + React 外壳 | 团队习惯决策，不影响需求本身 |
| Q4 | 建筑群实例拾取（P1）是否保留 | 取决于 M1 阶段实测性能 |
